Build a 3D portfolio site
with a video hero, step by step.

A plain-language walkthrough for generating the hero video and building the full scroll-driven 3D website using Claude Code — no technical background required to follow along.

Part One — The Hero Video
Generate the video that plays behind the headline.
This is the first thing visitors see — you at your desk, warm lighting, code on screen. Made in two passes with Google Flow: a still photo first, then animated into a short video.
01

Generate the still photo first

Before the video, you need one strong reference photo — the video tool animates this image. This was generated using Google Flow. The prompt below is the exact one used, written to leave empty space on the left for the headline text and keep the photo realistic instead of looking AI-generated.

Notice the "negative space on the left side" line in the composition section — that's intentional. It leaves room for your headline text to sit beside you in the hero, instead of covering your face.

02

Turn that photo into a video

Once you've got a still you like, upload it back into Google Flow and use it as the starting frame for an image-to-video generation. Give it a short line of dialogue so the character actually speaks instead of just sitting there:

Video Prompt — Google Flow (image-to-video) 
Character says these words: "Hi this is Ajay. I am a software engineer with 7 years of experience building enterprise systems with deep experience in Java, Spring Boot, AWS, and API development."

Upload the generated image as the reference, paste this as the prompt, and let it animate. Because the line is short and the framing was already locked in by the photo prompt, the motion stays natural — mouth movement and a little hand gesture, nothing exaggerated.

03

Clean it up

  • Mute any audio you don't want in the final loop — the site autoplays muted anyway
  • Trim it down if it runs long; 5–10 seconds is plenty for a looping background
  • Compress the file under 8MB so the site loads fast
04

Save the final file

Name it something simple like hero-video.mp4 and keep it somewhere easy to grab — you'll hand it to Claude Code in Part Two.

Part Two — Building the Website
Hand the instructions to Claude Code, let it build.
Claude Code is the builder. Your prompts are the instructions. You just answer questions and review the result.
01

Get your building blocks ready

  • The master prompt — describes all four 3D scenes, your job history, colors, fonts (full prompt below in Part Three)
  • The Scene 3 prompt — the floating skills graph, built separately (also in Part Three)
  • The hero video from Part One
02

Open Claude Code

Open it inside an empty project folder. It'll set up everything from scratch — you don't need to create any files yourself first.

03

Hand over the main prompt

Paste in the full master prompt and tell it to build the site. It already has the ui-ux-pro-max skill installed, so it'll apply that automatically for layout and polish — nothing extra needed from you here.

04

Let it build

  • Sets up the Next.js project
  • Installs the 3D tools — React Three Fiber, GSAP, Framer Motion
  • Builds each section: Hero, About, Experience, Skills, Education, Contact
  • Wires up scroll animation so the camera "flies through" the 3D world as you scroll

This takes a while. If it asks questions along the way, just answer in plain words.

05

Add your hero video

When it reaches the hero section, hand it your hero-video.mp4 from Part One. It'll wire it up as the background automatically.

06

Build Scene 3 separately

Paste in the dedicated Scene 3 prompt right after the main build — the floating skill nodes that light up when you hover a skill card. This is its own focused step.

07

Preview it

  • Does the video play smoothly in the hero?
  • Do the 3D scenes look right as you scroll?
  • Does hovering a skill card light up the right node in Scene 3?
  • Is your job history accurate and in order?
08

Fix anything that looks off

No code knowledge needed — just describe the change in plain words ("make the orange more red," "this animation is too fast") and Claude Code edits the code directly.

09

Push to GitHub

Once you're happy with it, ask Claude Code to push the project to your GitHub account so it's saved and backed up.

10

Deploy on Vercel

Connect the GitHub repo to Vercel (or have Claude Code do it). You'll get a live link to share — your own domain, or a free .vercel.app one to start.

Part Three — The Actual Prompts
Copy these straight into Claude Code.
These are the exact prompts referenced in Part Two. The first builds the whole site. The second builds Scene 3 — the floating skills graph — as its own focused piece right after.
A

The master build prompt

Paste this whole thing into Claude Code as your first message in a fresh project folder. It covers the tech stack, all four 3D scenes, your real job history, and the visual direction.

Master Prompt — Full Site Build 
Use the ui-ux-pro-max skill for this build. Apply it for the overall design system, layout decisions, spacing/typography scale, component composition, and visual polish across every section below — treat it as the governing design authority for this project.

TECH STACK
- Next.js 14+ (App Router) + TypeScript
- React Three Fiber + drei for the 3D scene/canvas layer (Three.js)
- Tailwind CSS for utility styling
- Framer Motion for text/element reveal animation
- GSAP + ScrollTrigger for scroll-driven 3D camera/scene transitions
- shadcn/ui for base components (buttons, cards, badges)
- Deploy target: Vercel

DESIGN REFERENCES
- 21st.dev hero patterns: staggered word-by-word headline reveal using Framer Motion, a mouse-follow radial glow effect behind hero content, an SVG/grid background with hover-responsive tiles for depth, and a trust-indicator stat strip under the CTA.
- Peachweb.io 3D web patterns: scroll-triggered 3D scene transitions where camera position/rotation animates through chapters as the user scrolls, keyframe-based object animation tied to scroll percentage (not time), ambient floating particles reacting subtly to cursor movement, and clean chapter-to-chapter transitions rather than abrupt cuts.

HERO SECTION (VIDEO-BASED)
Use the hero video (developer at a dual-monitor desk, warm cinematic lighting, code/architecture diagrams on screen) as the background.
- Full-bleed video background, object-fit cover, muted/autoplay/loop, with a subtle dark gradient overlay (bottom-heavy, ~40% opacity black-to-transparent) so text stays legible.
- Layer a 3D canvas (React Three Fiber) on top of the video using a transparent-background Three.js scene — an animated "code constellation" (nodes/edges referencing API architecture) drifting in 3D space with slight parallax on mouse move.
- Headline text overlay with a staggered word-by-word reveal animation:
  - Eyebrow line: SENIOR SQL & API DEVELOPER
  - Headline: Building enterprise systems that scale.
  - Subtext: 7+ years across finance, telecom, and insurance — Java, Spring Boot, AWS, and API architecture for systems handling millions in loan servicing volume.
- CTA buttons: "View Experience" (scrolls to timeline) and "Get in Touch".
- Scroll-down indicator bottom-center.

THE FOUR 3D SCENES (CONTINUOUS CAMERA PATH)
Build one continuous 3D world that the camera flies through as the user scrolls, driven by GSAP ScrollTrigger, through four distinct scenes. These four scenes must feel like one continuous camera path through one connected 3D world, not four separate widgets dropped on a page — that continuity is the single biggest thing that makes a 3D portfolio feel premium instead of gimmicky.

1) Hero — the code/node constellation described above, drifting over the full-bleed video background.

2) Experience Timeline — a "Database Engine Room" scene. A rotating 3D server-rack / database cylinder motif: stacked translucent disks (representing tables/indexes) with thin glowing lines (queries) pulsing between them. As each timeline card scrolls into focus, a query-line animates from the rack toward that card and lights up, visually tying the 3D object to the role being read. Subtle ambient pulsing glow synced to scroll velocity. Keep the warm amber accent threading through, with cooler blue-white highlights on the data lines for contrast.

3) Skills — an "API Constellation" scene. A 3D node graph where each skill category (Languages, Backend, Cloud/Infra, Database, Security, Frontend) is a glowing cluster of nodes in 3D space, connected by thin edges. The camera slowly orbits the whole graph. On hover/tap of a skill card in the UI, the matching 3D node pulses brighter and its connections highlight. This reuses the hero's node/edge visual language so the site feels cohesive.

4) Contact/footer — a "Closing Orbit" scene. Slow down dramatically: a single soft-glowing orb (or an extruded 3D wordmark) gently rotating, with the same particle field from the hero now sparse and slow. This is deliberately the least busy scene on the site — the "exhale" moment signaling the end. CTA buttons sit in front of this scene with strong contrast so they don't compete with it.

VISUAL DIRECTION
- Palette: warm cinematic dark base (near-black, around #0D0D0D) matching the hero video's warm amber lighting, with a single warm amber/orange accent (around #E8923C, picked from the video's lamp glow) for CTAs and highlights, plus cooler blue-white highlights for data/query lines in Scene 2.
- Typography: a clean technical sans (Inter or Geist) for body text, with a slightly heavier display weight for headlines — mix bold/regular within headline lines for emphasis.
- Motion: scroll position drives 3D camera/object state (GSAP ScrollTrigger + R3F), not just opacity fades. Hover states get subtle 3D tilt/depth, not flat color changes. Respect prefers-reduced-motion and fall back to simple fades for all four scenes.
- Performance: lazy-load the 3D canvas, keep particle/geometry counts modest, keep the hero video compressed and under roughly 8MB, target a Lighthouse performance score of 85+.

B

The Scene 3 prompt (skills graph)

Once the main build is done, paste this in as a focused follow-up to build the floating skills graph specifically — the 3D scene that lights up nodes when you hover the matching skill card.

Scene 3 Prompt — API Constellation 
Use the ui-ux-pro-max skill for this component.

Build a React Three Fiber (drei) component called ApiConstellationScene for a Next.js 14 / TypeScript portfolio site. This is the 3D background scene for the Skills section of a developer portfolio.

CONCEPT
The tech stack rendered as a living constellation: each skill category is a glowing cluster of nodes in 3D space, connected to other nodes in its cluster by thin edges, with thin cross-cluster edges showing how categories relate (e.g. Backend to Database, Cloud/Infra to Backend). It should feel like a continuation of the hero section's "code constellation" — same visual language, more structured now that we're past the hero.

DATA STRUCTURE
Six clusters, positioned at different points in 3D space so the whole graph reads as one connected structure, not six separate blobs:
- Languages: Java 8/11/17, SQL (T-SQL), TypeScript
- Backend: Spring Boot, Hibernate/JPA, Microservices, REST/SOAP APIs, Kafka
- Cloud/Infra: AWS (EC2, S3, RDS, SQS), Docker, Kubernetes
- Database: SQL Server, PostgreSQL, Oracle/MySQL, Query Optimization, Stored Procedures
- Security: IAM, RBAC, OWASP, Fortify, Black Duck
- Frontend: React, Next.js

Each skill is one node (a small glowing sphere or icosahedron). Each category is a cluster of its nodes positioned close together, with a slightly larger "anchor" node or label floating at the cluster's center.

VISUAL SPEC
- Background: transparent (this canvas sits behind/within the page, not as a full opaque background).
- Nodes: small emissive spheres, warm amber as the base node color.
- Edges: thin lines — within-cluster edges in dim amber, cross-cluster edges in a cooler blue-white so the "system-level" connections visually read as distinct from "same category" connections.
- Idle motion: nodes drift very slightly — a subtle floating/breathing animation with a small sine-wave offset per node, low amplitude — never fully static, never distracting.
- Camera: a slow continuous orbit around the whole graph, barely perceptible, just enough to give the scene life.
- Lighting: minimal — mostly self-illuminated via emissive materials, plus one soft ambient light and one subtle point light near the camera for depth.

INTERACTIVITY (the key feature)
This scene must sync bidirectionally with the 2D skill cards rendered in the DOM:
- On hover or tap of a skill card in the UI, the matching 3D node should scale up slightly (a spring animation, not an instant snap), increase emissive intensity noticeably, and brighten its connected edges within that cluster.
- On hover/click of a category label in the UI, brighten the entire cluster (all nodes plus internal edges) at once.
- Expose this through a simple prop/context API, e.g. <ApiConstellationScene activeSkill={hoveredSkillId} activeCategory={hoveredCategoryId} />, so the parent page component can drive it from normal React state (onMouseEnter/onMouseLeave on the skill cards).

SCROLL BEHAVIOR
- This scene should fade/scale in as the Skills section enters the viewport.
- If implementing a continuous camera flythrough across the whole site, this scene's camera position should be reachable by the same master scroll timeline that also drives the Database Engine Room and Closing Orbit scenes — but the component itself should still work standalone if mounted in isolation; don't hard-couple it to a single global timeline.

PERFORMANCE & ACCESSIBILITY
- Keep total node count reasonable — around 25 to 30 nodes across all clusters is plenty, don't over-decorate.
- Lazy-load this canvas so it doesn't block initial page load.
- Respect prefers-reduced-motion: disable camera auto-rotation and node idle-drift, keep nodes static but still interactive on hover.

DELIVERABLE
A single self-contained component file (e.g. components/scenes/ApiConstellationScene.tsx) plus a short usage example showing how the Skills section page component would pass activeSkill/activeCategory state into it based on which skill card is currently hovered.

If Something Goes Wrong
Common hiccups, plain fixes.
Video doesn't play on the live site
It's probably too large a file. Compress it smaller and re-upload.
3D scenes look laggy or slow
Ask Claude Code to reduce the number of floating shapes or particles — fewer objects means smoother performance on most computers.
Site looks broken on phone
Tell Claude Code "this needs to work well on mobile too" and point out exactly what looks wrong.
You don't like a color or font
Just say so in plain words — no technical terms needed. Claude Code will make the change directly.
